# Changelog

All notable changes to GAUNTLET. Versions follow [SemVer](https://semver.org);
the CLI's exit codes and the database are the compatibility surface.

## 0.2.0 — 2026-10-20

From a report to a platform: GAUNTLET can now be *seen*, read by CI, and asked
about history — with zero new dependencies.

### Added
- **`gauntlet serve`** — a local, read-only dashboard (stdlib `http.server`)
  over the run database: runs with a trend chart and a diff picker, a full
  report per run, any-two-runs diff, per-step stability, and a log viewer that
  highlights violation lines. JSON under `/api/*`. Binds to localhost by
  default and reloads the runs page when a new run lands.
- **Rebuilt HTML reports** (`--html`) — KPIs, the flow DAG with the
  duration-weighted critical path, a timeline of step windows, filterable
  violations, and the waiver debt by owner. Light/dark, offline, print-friendly.
  `diff --html` renders a diff page.
- **`--junit`** on `run` and `report` — JUnit XML. FAIL → `<failure>`, TIMEOUT →
  `<error>`, SKIPPED → `<skipped>`; WAIVED passes with a `gauntlet.status`
  property and the waived errors in `system-out`.
- **`--markdown`** on `run`, `report` and `diff` — GitHub-flavoured summaries
  for `$GITHUB_STEP_SUMMARY`, with the DAG as Mermaid. `-` writes to stdout.
- **`gauntlet stats`** — pass rate, flips, flaky retries, mean/p95 duration and a
  verdict per step over the last N runs.
- **`gauntlet graph`** — layers and longest chain as text, Mermaid or DOT.
- **Run refs** — `latest` and `latest~N` wherever a run id is accepted.
- `diff --json`, `history --flow`, `gauntlet --version`.
- Runs record each step's `start_s`/`end_s` window and `attempts`, the waiver
  owner, the flow's DAG, and the git commit and branch (detected, or from
  `GAUNTLET_GIT_COMMIT` / `GAUNTLET_GIT_BRANCH`, with CI fallbacks).
- `GAUNTLET_RUNS_DIR` to relocate run artifacts and the database.
- Colored terminal output on a TTY (`NO_COLOR` / `FORCE_COLOR` honoured).
- CI: lint, a test matrix (Python 3.10–3.13 on Linux, plus macOS and Windows),
  and a smoke job that publishes JUnit + an HTML report + a step summary and
  proves the diff gate trips on an injected regression.
- Website: an interactive in-browser playground, a dashboard tour, and real
  sample reports generated by `scripts/build_site_demo.py`.

### Changed
- Run duration comes from step windows (millisecond precision); v0.1 runs fall
  back to their second-precision timestamps.
- Reports list steps in flow order rather than completion order.
- The database gained columns and a `run_edges` table; v0.1 databases are
  migrated in place on open.

### Fixed
- Two runs starting in the same second sorted by their random id suffix, so
  "newest" could be the wrong run. Insertion order now breaks the tie.
- Piping output on Windows (cp1252) could crash on `→` and friends; the CLI now
  degrades the glyph instead, and `stats` falls back to ASCII.
- `gauntlet history | head` no longer ends in a `BrokenPipeError` traceback.

## 0.1.0 — 2026-07-12

The core loop: YAML flows validated into a DAG, a ready-set scheduler running
real subprocesses in their own process groups, regex rulepacks and waivers,
SQLite history, run-to-run diff, a single-file HTML report, per-step retries
with honest flaky marking, and a cross-platform test suite.
